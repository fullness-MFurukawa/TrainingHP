# BDDで学ぶAI協働型テスト仕様書作成 コース紹介HTML作成 プロンプト記録

## 1. キャッチコピー

**指示：** キャッチコピーを案と観点をセットで出してください。

**選定：** 案2（「AIに任せる」という誤解を正す視点）
> AIに任せるのではなく、AIと考える。BDD×AIで変わる、テスト仕様書作成の常識。

---

## 2. 研修概要

**指示：** 研修概要をいくつか案を出してください。

**選定：** 案B（課題提起から入る構成）
> 「AIが自動でテスト仕様書を作ってくれる」——そんな期待と現実のギャップを正しく理解することから始まります。本研修では、AIの得意・苦手を踏まえた上で、BDD（Gherkin）とGitHub Copilotを組み合わせた協働型テスト仕様書作成のスキルを習得します。

---

## 3. 本研修の特徴

**指示：** 本研修の特徴を3つ、案と観点をセットで出してください。

**選定：** 案B（コードレス・実践演習を強調）
> 🧩 プログラミング不要で受講できる
> 💻 GitHub Copilotを使った段階的な演習
> 🗣️ AI時代のテストマネジメントを議論する

---

## 4. 到達目標

**指示：** 到達目標（受講後に身につくスキル）を、案と観点をセットで出してください。

**選定：** 案A（スキル・できること視点）
> - AIが作成したテスト仕様書の品質を評価し、足りない点・おかしい点に気づける
> - BDD（Gherkin）を用いて、AIに伝わる構造化されたテストシナリオを作成できる
> - GitHub Copilotを活用してテスト仕様書を作成し、プロンプトを改善して精度を高められる

---

## 5. こんな企業にお勧め

**指示：** こんな企業にお勧めを、案と観点をセットで出してください。

**選定：** 案A＋案Bの組み合わせ（テスト品質改善・組織全体のAI活用推進視点）
> - テスト担当者・QAチームにAIを正しく活用するスキルを習得させたい
> - 「AIにテストを任せればいい」という誤解をチームに正したい
> - BDDの導入を検討しており、AI活用と合わせて実践したい
> - エンジニアだけでなくQA・ビジネスアナリストも含めた組織全体でAI活用を進めたい
> - コードを書かないメンバーにもAI協働型テスト設計を習得させたい
> - GitHub Copilotを導入済み、またはこれから導入を検討している

---

## 6. カリキュラム詳細

**指示：** 1日間のカリキュラム詳細をマークダウンの表で作成してください。

**選定：** 以下の構成で確定

| 日程 | 章・学習テーマ | 学習内容・習得スキル |
|------|--------------|-------------------|
| 1日目 | 第1章：研修イントロダクション | 研修のゴール・AI時代のテストとは・AIを使うときの基本スタンスを理解する。AIは「答えを出す道具」ではなく「思考を助ける道具」であるという基本姿勢を習得する。 |
| 　 | 第2章：AIとテスト仕様書作成 | AIが得意なテスト仕様書作成タスク（観点の列挙・入力値パターン・境界値候補・表形式整理）とAIが苦手なタスク（曖昧な仕様・業務ルールの暗黙知・重要度の判断）を理解する。AI生成仕様書の品質を左右するのは入力情報の質であることを習得する。 |
| 　 | 第3章：BDD（Gherkin）の基礎 | TDDからBDDへの進化・Given/When/Thenによるシナリオ記述・人にもAIにも伝わる構造化された仕様の書き方を習得する。 |
| 　 | 第4章：Gherkinによる実務的なシナリオ | Feature・Background・Data Tableを用いた実務的なシナリオ記述を習得する。シナリオが仕様として再利用できることを理解する。 |
| 　 | 第5章：演習で利用するアプリケーション | 演習で利用する商品管理Webアプリケーションのログイン・商品検索・商品登録の要件を確認し、アプリケーションを実際に操作して振る舞いを把握する。 |
| 　 | 第6章：テスト仕様書作成演習 | プロンプト設計の考え方を習得する。演習1（人によるシナリオ作成）→演習2（AIによるシナリオ生成）→演習3（AIによるテスト仕様書作成）→演習4（プロンプト改善）→演習5（グループによるテスト仕様書作成体験）→ディスカッション（AI時代のテストマネジメント）を通じてAI協働型テスト設計を実践的に習得する。 |

> ※ 特別なAI知識・プログラミング経験は不要です。

---

## 7. 受講にあたっての前提知識

**指示：** 前提知識・スキルを、案と観点をセットで出してください。

**選定：** 案A（ハードルを最低限に設定・非エンジニアも含む幅広い対象者向け）
> - ソフトウェアテストの基本概念（テストケース・テスト仕様書・正常系・異常系）を理解していること
> - 基本的なPC・ブラウザ操作ができること
> - GitHubアカウントを保有していること
