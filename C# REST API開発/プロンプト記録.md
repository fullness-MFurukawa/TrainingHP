# C# REST API開発コース キャッチコピー作成プロンプト記録

> キャッチコピーを決定するまでのプロンプト手順書です。
> 同じ作業を再現する際は、以下の順序でClaudeに入力してください。

---

## 事前準備

研修コースのスライド資料（.pptx形式）を用意してください。
Claudeがコースの内容・特徴・強みを把握した上でキャッチコピーを生成します。

---

## STEP 1｜コース内容の読み込み

```
スライドをアップするので、読み込んでください。
```

> スライドファイル（.pptx）をアップロードします。
> Claudeがテキストを抽出し、章立て・学習内容・特徴を把握します。

---

## STEP 2｜品質・将来性の評価

```
最初に、この研修コースの品質、将来性を評価してください。
```

> コースの強み・改善点・将来性をClaudeが分析します。
> この評価内容がキャッチコピーの方向性の土台になります。

---

## STEP 3｜評価のMarkdown化と差別化の明確化

```
提示していただいた内容にMarkdownを作成してください。
DDDをベースにしているところは差別化できませんか?
```

> 評価内容をMarkdownファイルとして保存します。
> 同時に、このコース最大の差別化ポイント（DDD）を明確に言語化するよう依頼します。
> ここで差別化ポイントを整理しておくと、以降のキャッチコピーの質が上がります。

---

## STEP 4｜最初のキャッチコピー案の生成

```
この研修にキャッチフレーズをつけるならどのようなものがいいでしょうか？
いくつかの案を提示してください。
```

> 複数案（5〜6案）が提示されます。
> コースの特徴（DDD・セキュリティ・設計原則）をベースにした案が生成されます。

---

## STEP 5｜対象者を絞ったキャッチコピーの生成（若手エンジニア向け）

```
若いエンジニア層を対象すると思うので、そのあたりも考慮してください。
```

> 対象者の課題感・感情・キャリア意識に寄り添った言葉に調整されます。
> 「なんとなく動く」「先輩のコードが読めない」など、若手特有の悩みに刺さる表現になります。

---

## STEP 6｜対象者を絞ったキャッチコピーの生成（事業会社向け）

```
自社のシステムを社内で開発している事業会社などに向けたキャッチコピーをお願いします。
```

> 内製開発チームが抱える課題（外注依存・技術負債・変更耐性）に寄り添った表現になります。
> 「仕様変更が怖くないチームをつくる」「触りたくないコードを次の世代に残さない」など、
> 組織・チーム視点の言葉が生成されます。

---

## STEP 7｜汎用的なキャッチコピーの生成

```
ありがとうございます。いろいろな立場の方が見ると思うので、
汎用的なキャッチコピーをお願いします。
```

> 特定の立場・職種に偏らず、誰が読んでも「自分ごと」として受け取れる表現に調整されます。
> 「動くだけでなく、変えられるAPIをつくる」「設計原則が身につくと、どの現場でも通用する」
> など、普遍的な価値を訴求する案が生成されます。

---

## STEP 8｜自分のアイデアをぶつけてみる

```
例えばですが、設計原則が身につくAPI開発ハンズオンというのでどうしょうか?
```

> 自分のアイデアをそのままClaudeにぶつけます。
> Claudeがそのまま使う案・少し磨いた案を複数提示してくれます。
> ここで「これが近い」と感じたものをベースに最終調整します。

---

## STEP 9｜確定

```
設計原則が身につくREST API開発ハンズオンに決めました。
```

---

## 確定したキャッチコピー

```
設計原則が身につくREST API開発ハンズオン
```

**選定理由：**
- シンプルで誰にでも伝わる
- 「設計原則が身につく」でDDDをベースにした差別化が一言で表現できる
- 「REST API開発ハンズオン」で研修内容と形式が明確に伝わる
- 若手エンジニア・事業会社・SIerなど、どの立場からも違和感なく受け取れる

---

## ポイント・コツ

| ポイント | 内容 |
|----------|------|
| 評価→差別化→コピーの順で進める | いきなりコピーを作るより、まず強みを整理してからの方が質が上がる |
| 対象者ごとに案を出してもらう | 若手・事業会社・汎用と段階的に絞ることで、最終的に「誰にでも刺さる言葉」に辿り着きやすい |
| 自分のアイデアをぶつける | 「〇〇というのはどうか」と投げると、Claudeがバリエーションを展開してくれる |
| 形式説明になっていないか確認する | 「ハンズオン」などの形式語は内容説明になりやすい。差別化の言葉と組み合わせて使う |
| 最後は自分で決める | 複数案の中から「これだ」と思うものを選ぶのは人間の判断。Claudeは選択肢を広げる役割 |

---

## 全体の流れまとめ

```
STEP 1｜スライドをアップロードして内容を把握させる
STEP 2｜品質・将来性の評価を依頼する

STEP 4｜最初のキャッチコピー案を複数生成する
STEP 5｜若手エンジニア向けに調整する
STEP 6｜事業会社（内製開発）向けに調整する

```

# C# REST API開発コース 研修概要作成プロンプト記録

> 「本研修について」「本研修の3つの目的」を再現するためのプロンプト手順書です。
> Claudeに対して、以下の順序で入力してください。

---

## 事前準備

以下を用意してください。

- 研修コースのスライド資料（.pptx形式）
- 確定したキャッチコピー（文章のトーンの基準になります）

> 本コースの確定キャッチコピー：**「設計原則が身につくREST API開発ハンズオン」**

---

## SECTION 1｜本研修について

### STEP 1｜文章の生成

```
それでは次に、研修概要の文書作成をお願いします。
```

> スライドをアップロード済みであればそのまま送信します。
> Claudeがコース内容をもとに複数のトーンで文章案を提示します。

### STEP 2｜案の選択

```
案Aにします。
```

> 提示された案（A / B / C）から選択します。
> 今回は案A（設計力の習得を前面に出したトーン）を選択しました。

### 確定文（案A）

本研修は、C#および.NETを用いたREST API開発を、ドメイン駆動設計（DDD）をベースに体系的に学ぶハンズオンプログラムです。

「動くコードが書ける」から一歩進み、変更に強く・テストしやすく・チームで共有できる設計を身につけることを目的としています。ドメイン層・インフラストラクチャ層・アプリケーション層・プレゼンテーション層の4層アーキテクチャを実装しながら、依存性逆転の原則（DIP）・Repositoryパターン・Unit of Workなどの設計原則を体得します。

さらにJWT認証・HTTPS・CORS・HttpOnly Cookieを第二部として独立した章で扱い、セキュリティを考慮した実践的なREST APIの構築まで一気通貫で学びます。

---

## SECTION 2｜本研修の3つの目的

### STEP 1｜文章の生成

```
次は、本研修の3つの目的をお願いします。
```

> 「本研修について」で選んだ案のトーンを引き継いで文章案が生成されます。

### STEP 2｜案の選択

```
案Bにします。
```

> 今回は案B（「できるようになること」視点で整理した受講者目線型）を選択しました。

### 確定文（案B）

本研修では、以下の3つを習得することを目的としています。

**1. 変更に強い設計ができるようになる**
DDDの4層アーキテクチャと設計原則（DIP・Repository・Unit of Work）を実装を通じて体得し、仕様変更・技術変化に強いコードを書けるエンジニアを目指す。

**2. REST APIを設計から実装まで自走できるようになる**
ASP.NET Coreの主要機能を活用し、エンドポイント設計・ドメイン実装・例外処理・OpenAPI/Swagger対応まで、一貫したREST APIを独力で構築できる力を養う。

**3. セキュリティを自分の手で実装できるようになる**
「知っている」を「できる」に変える。JWT認証・HTTPS・CORS・HttpOnly Cookieを実際に実装することで、セキュリティを他任せにしないエンジニアへの第一歩を踏み出す。

---

## ポイント・コツ

| ポイント | 内容 |
|----------|------|
| キャッチコピーを先に確定させる | コピーのトーンが文章全体の方向性の軸になるため、先に確定しておくと一貫性が出る |
| セクションごとに1つずつ進める | まとめて依頼するより、1セクションずつ確認しながら進める方が精度が高い |
| トーンを統一しなくてよい | 「本研修について」と「目的」で異なる案（A・B）を選んでも問題ない。内容が補完し合う |
| 受講者視点 vs 技術視点で使い分ける | 概要文は技術軸（案A）、目的文は受講者視点（案B）のように役割で使い分けると読みやすくなる |
| スライドは最初に一度読み込めばよい | 同じ会話内であれば、再アップロードは不要 |

---
